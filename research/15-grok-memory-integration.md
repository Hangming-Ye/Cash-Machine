# Grok Bot 记忆接入调研：面向 spec001 的设计依据

2026-09-20。主 agent 综合，另由 3 个 gpt-5.6-sol / medium 子 agent 分别核验产品边界、组件源码及任务案例。范围：真实 Grok Bot 产品的可配置入口、现有记忆组件及任务适配。本文为 plan 的研究输入，不是实施方案已经通过验收的声明。官方产品文档、市场模板、源码／组件文档与本项目设计推断分别标明；没有操作用户 Grok 账户、安装服务或读取券商凭证。

## 核心结论

Grok Bot 可配置的入口是角色说明、Skill、Routine 指令以及共享电脑上的文件和工具。不能按可自定义 agent harness 的方式设计：没有证据证明用户能替换原生记忆后端、拦截每次模型调用、直接操作内部上下文，或配置原生模型选型。

因此，“再注入”在本项目应先落实为：任务触发后，Bot 按 Skill 读取与当前研究相关的工作摘要和经验；专员交接同时给出短摘要与明确的证据路径。它不是隐形的底层 prompt hook。能否可靠执行必须在目标产品内验证，不能由文件写入成功或工具调用成功推定。

当前优先验证 **原生 Skill + 共享研究文件 + 必要的小型检索／写入辅助**。Mem0 可作为后续检索与更新组件候选，LangMem 和 Letta 可借鉴整理方法；不为接入记忆迁移 Bot 平台，也不建立新调度器。

| 能否指定原生模型 | 设置文档说明模型由平台管理，无 model picker | 记录可见版本／模型信息；不可见就如实注明，用实际产品测试 | 保证每个 Bot 固定使用 Grok 4.5／4.6；通过普通 API 配置原生 Bot |

以上“未发现”只涵盖本轮官方页面，不等于证明不存在内部功能。设计不得依赖尚未证实的接口。

## 记忆路径按任务组织

这些是可组合的工作特点，不是三个服务或固定任务类型枚举。

| 任务 | 任务开始读取 | 任务结束整理 | 更新／压缩原则 | 注入时的常见失败 |
| --- | --- | --- | --- | --- |
| 定时 | 上次有效基线、当前关注范围、未解决问题，再拉当前数据 | 本轮有依据的增量、已处理来源和仍未验证事项 | 无变化不重复创建经验；普通周期读写即可，不另建定时服务 | 把旧报价当当前值；同一条新闻多次计为证据；漏读基线 |
| 长期 | 当前主题摘要、关键假设、反证、已否定路径及下一验证点 | 更新当前理解；新经验合并入同主题或通用方法记录 | 关键转折保留来源；合并重复观点但保留未决冲突，不无限堆叠日报 | 重开会话后从头研究；旧假设被无痕覆盖；反证被摘要删除 |
| 重分析 | 按子问题取得材料索引、适用经验、相关分析记录和计算输入 | 阶段结论、支撑依据、适用条件、未完成分析及产物路径 | 压缩的是工作说明和经验；原始证据、计算输入与结果仍可回查 | 只读旧结论而不读依据；整库塞入上下文；条件变化仍复用旧计算 |

工作材料可有三种用途：原始依据、当前研究摘要、跨任务经验。文件或存储实现不必分为三套。计算结果仍由确定性工具产生；经验只帮助提出检查项和反例，不能代替统计验证。

## 最小交互方式（设计推断，未部署）

### 原生入口

- Description：告诉 Bot 研究资料的位置、执行哪份方法，以及开始研究前读取资料。短而稳定，不重复放全部历史。
- Skill：完整包含“读取相关记忆 → 当前研究／验证 → 提炼更新”的步骤及交付要求。定时、长期、重分析按当前问题组合步骤。
- Routine：只负责既有触发、范围和 Skill 引用；不在 Routine 中复制另一套研究逻辑。
- 专员消息：携带任务、必要摘要及明确文件定位。关键摘要直接出现在消息中，可回查的大材料用路径；不只发一个含糊的文件夹。

### 写入与压缩

初版可以由研究负责人整理自己负责的主题摘要，专员只提交其研究材料，避免多个 Bot 同时覆盖同一总结。这个分工是写入约定，不是新建调度系统。若同主题确需多任务并发写入，再用窄工具做版本检查／原子写入；不由此增加任务锁、租约或全套分布式状态机。

整理在已有研究结束或既有复盘任务中做即可。原生 Bot 可按具体提示提炼经验，无需先购买另一个模型服务。若测试表明其提炼质量不够，再评估独立调用更合适模型的成本与接入；不能假定原生订阅自动提供 API 额度。

若记忆较少，按证券／主题索引取对应文件最直接。跨主题经验检索漏召回或材料量明显增加时，再测试语义检索组件。若有同义概念跨公司关联，索引必须允许相关主题召回，不能把精确股票代码当唯一过滤。

### 可控边界

辅助程序可以控制返回材料的长度、筛选条件、去重和写入；不能控制原生 Bot 的整个上下文窗口。应称“交给 Bot 的记忆材料预算”，避免承诺“控制模型总上下文”。Bot 读取的工具结果也可能被平台压缩，长任务应在下一阶段显式回读所需材料；不依赖不存在的压缩通知钩子。

读取或整理失败时，报告本次未获得历史支持／未完成经验更新，继续能独立完成的当前研究，不声称记忆已完整使用。仅“我已读取”的文字回执不算效果证据，还要检查可见工具／文件读取记录（产品提供时）与后续分析是否正确采用相关经验、反证和条件。产品内部完整上下文不可见时，不声称观测了底层注入；以实际交给专员的材料和行为样例作为证据。

## 组件选型与复用证据

详见 [现有组件与源码调研](14-memory-consolidation.md)。Mem0 的 CLI 提供实际 shell 路径，但面向其 Platform；LangMem 的 manager 可独立调用，但引入框架依赖与独立模型调用；Letta 的自动上下文管理依赖自己的运行环境。因此优先复用整理方法，组件候选按具体缺口再测试。外部库具有能力不代表能替换 Bot 内部记忆。

## 必须做的小样例验证

下表是后续可执行验证设计，本轮尚未执行。采用虚构公司与脱敏材料，无需账户信息。

| 验证 | 输入与操作 | 观察和通过条件 | 不通过时优先调整 |
| --- | --- | --- | --- |
| 原生入口 | 同一研究 Skill，分别从新会话、已有 Routine、专员交接运行 | 三种入口都能读取指定研究摘要，结果使用其中关键条件；现有会话成功不替代新会话证据 | 缩短入口指令，在 Routine／交接显式引用 Skill 和短摘要；不加后台控制器 |
| 定时增量 | 两轮相同资料后加入一个实质变化，混入过期行情 | 重复资料不成为新证据；第三轮能解释变化；旧行情不当现价 | 明确基线与日期，必要时用确定性去重辅助 |
| 长期续研 | 一个主题含支持材料、已否定路径和未决反证，换新会话 | 能从下一验证点继续；保留反证，说明旧路径为何无效 | 调整主题摘要字段和任务前读取顺序 |
| 重分析 | 提供推导依据和旧结论，再改变一个关键假设 | 找回来源，重算／重评受影响部分；不机械复用旧答案 | 缩小阶段材料、增强出处索引和适用条件 |
| 压缩与经验 | 重复教训、相关反例、过时项、无关项混合 | 记录压缩前后长度；无关项不注入；重复合并、反例保留且来源可回查 | 改提炼指令，必要时比较 Mem0 组件结果 |
| 使用效果 | 同一问题分别提供／不提供已整理经验 | 有记忆条件补上历史暴露的检查遗漏；不要求措辞相同或投资结论一定改变 | 若只引用不改变检查行为，视为未证实实用性 |
| 共用文件 | 研究 Bot 交付，另一 Bot 从新任务读取 | 得到正确材料，未覆盖他人原始产物；失败记录具体问题 | 明确主题写入负责人；只有真实冲突才加窄写入辅助 |

样例重复次数、材料预算和可接受成本在实际环境记录，不提前编造原生上下文上限或可靠率。失败原因必须分成入口未调用、材料未召回、摘要错误、读取后未使用，避免一律更换“记忆库”。

## 进入 plan 的结论与剩余未知

可据文档开始设计：原生入口、共享文件载体、三类任务记忆内容、提炼与回查方法、任务级注入及轻量验证顺序。

仍需现场核验：当前账户私有 Skill／Routine 对此方法的执行率；云电脑的实际运行依赖与可达网络；长任务中材料被平台压缩后的表现；若选择 MCP，安装与认证具体路径；如选择外部记忆组件，其模型／embedding 配置与费用。未验证这些，不能把某组件写成已经完成集成，也不能保证原生自动注入。

plan 应优先给出原生文件路径的最小垂直样例，随后根据问题增加必要组件。未做这些小样例不妨碍拟定验证步骤，但不足以宣称最终技术选型和 Grok 记忆效果已经确定。
