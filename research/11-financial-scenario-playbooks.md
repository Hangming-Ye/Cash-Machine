# 金融研究场景手册：把架构落成固定任务

本稿把三条研究链改写成可重复运行的任务。目标不是让 Grok 4.5/4.6 一次完成“全能投研”，而是让程序固定数据、计算和状态，让模型只做有限的金融判断。以下技能、MCP 与 CLI 均只作为研究材料；未安装、未调用外部服务、未读取凭证。

## 一、所有场景共用的执行合同

每次运行只允许一个 `task_type`、一个对象集合和一个数据截点。程序先生成研究包，模型只能引用包内 `evidence_id`，输出经程序验收后才能发布。

- 程序负责：实体匹配、交易日/时区、取数与去重、时间戳、单位币种、公式、估值表、回测、状态迁移、预算和幂等。
- 模型负责：解释驱动、比较相反假说、判断证据强弱、写证伪条件、在给定候选中选择结论。
- 时间字段固定为 `event_at / published_at / known_at / fetched_at / as_of / revision`；历史研究只可读 `known_at <= decision_at` 的材料。
- 行情、持仓、共识和财报必须各报自己的截至时间；IBKR T+1 快照不能被描述为当前实时敞口。
- `action` 仅有 `BUY / SELL / WATCH`；另设 `decision_state=actionable / insufficient_data / needs_review`。缺数据不是中性，也不能自动写成 `WATCH`。
- `WATCH` 只表示证据完整后，风险回报仍不足以买入或卖出；`insufficient_data` 必须列缺什么、谁补、何时再查。
- 价格输出拆为公允价值区间、最高可接受买入价、减仓/退出条件、技术时点；技术位不能改变基本面公允价值。
- 估值随阶段选方法：早期线索只给里程碑和反推估值；尚未盈利用单位经济/收入情景和现金跑道；成长股用驱动式 DCF 加同阶段可比；周期股用中周期盈利；成熟股用 FCF/股息与可比；事件股用概率加权价值。
- 同一工具因参数问题最多修正一次；401、权限缺失和两次相同服务错误直接转阻塞。空结果写“本次未召回”，不能写“没有该事实”。

固定系统提示词可保持很短：

> 你只完成给定 TASK_TYPE。先检查输入状态和截至时间；只引用 EVIDENCE_IDS。按 ANALYSIS_STEPS 顺序回答，不新增指标，不自行取数，不做算术。缺必填项输出 INSUFFICIENT_DATA；证据冲突输出 NEEDS_REVIEW。事实、观点、推断分开。最后只给规定 OUTPUT_FIELDS，并写一条最强反证与下一检查条件。

## 二、首发 6 个场景

### S1 持仓/自选每日行动卡

- 支柱：持仓/自选；触发：每个交易日收盘后，或用户说“今天怎么看”。
- 输入：只读持仓与自选快照、最新合格报价、上一版判断、最新事件簇、估值假设、已登记风险约束。
- 程序任务：对齐证券/币种/持仓时点；计算价格变化、区间回报和估值敏感性；只把“相对上一版有变化”的票送给模型。
- 分析 1：先判断新信息属于事实变化、预期变化还是纯价格变化。
- 分析 2：检查原论点的支持项、证伪项和催化剂是否改变。
- 分析 3：用程序给出的悲观/基准/乐观价值区间比较当前价，不自行平均外部目标价。
- 分析 4：在组合约束和数据状态允许时选 BUY/SELL/WATCH，并给转判条件。
- 输出：一张手机卡，含变化、行动、价格区间、最强理由、最强反证、下一检查日、持仓/报价时点。
- 失败：报价 stale、持仓延迟或估值输入缺失时为 `insufficient_data`；若信息完整但赔率一般才是 `WATCH`。
- 来源与复用：主架构持仓卡；`thesis-tracker`、`portfolio-risk-management`、`scenario-sensitivity-generator` 的行动规则；复用判断结构，不复用账户动作或未经验证评分。

### S2 盘中事件与价格阈值升级

- 支柱：持仓/自选；触发：关注标的出现新公告、财报、监管事项、可信新闻，或价格越过已登记阈值。
- 输入：事件原文/公告、发布时间、首次发现时间、去重后的转载簇、事件前后价格和原判断。
- 程序任务：聚类转载；计算事件窗口和阈值命中；检查公告原文、报价新鲜度与是否已在上一版中处理。
- 分析 1：把事件标为已证实事实、管理层陈述、分析师观点、传闻或我方推断。
- 分析 2：说明影响路径是收入、利润率、现金流、估值倍数、催化剂时点还是组合风险。
- 分析 3：比较至少一个相反解释；价格同向反应只作描述，不作因果证明。
- 分析 4：只有事件改变论点、价值区间或退出条件才升级行动卡，否则静默归档。
- 输出：变化警报或“不升级”回执；警报必须包含原文证据、影响项、行动是否改变和下一证据。
- 失败：只有摘要/社媒线索时进入待核实，不生成 BUY/SELL；同一事件不重复通知。
- 来源与复用：`market-news-analyst` 的事件分类、反应与归因框架；同舟 `doc_search__`/事件窗口；只复用流程，取消默认 10 天、英文和大盘优先限制。

### S3 财报前预演

- 支柱：持仓/自选；触发：确认财报日前 5 个交易日，或用户要求财报前计划。
- 输入：已确认/推定日期、上一季实际值、公司指引、带冻结时间的共识、3–6 个公司关键 KPI、价格/期权背景、当前论点。
- 程序任务：统一财季与 GAAP/非 GAAP 口径；计算共识与指引差、历史误差、情景表；日期仅在官方确认后写精确日历。
- 分析 1：定义市场门槛：市场已期待什么，而不只是“是否同比增长”。
- 分析 2：识别最可能驱动股价的 KPI、指引和 EPS 质量陷阱。
- 分析 3：写 bull/base/bear 的业务条件、估值影响和各自可观察证据。
- 分析 4：生成 3–5 个电话会问题，每个附 listen-for 和 falsifier。
- 输出：财报前卡，含预期门槛、关键 KPI、情景反应、不要做什么、财报后立即核查项。
- 失败：缺带时点的共识或期权事件隔离不足时只给预演框架，设 `decision_state=needs_review`，不发布新的行动结论，也不能称可交易信号。
- 来源与复用：WorkBuddy `earnings-tracker` 的日历/分层状态；`earnings-preview` 的 expectation bar、EPS quality 和场景；复用工作流，不复用其推送已运行声明。

### S4 财报后论点更新

- 支柱：持仓/自选；触发：财报、公告和电话会材料到齐，或财报后首个合格交易时点。
- 输入：官方财报/业绩公告、电话会、公司指引、冻结的财报前预演、共识、价格反应、上一估值模型。
- 程序任务：抽取并核对 actual/consensus/guide；做 EPS 质量桥、模型差异和事件窗口；保留财报前假设原貌。
- 分析 1：逐项回答收入、利润率、KPI、现金流和指引是超预期、符合还是不及预期。
- 分析 2：把一次性税项、资产处置、投资公允价值、汇率、重组等与持续经营分开。
- 分析 3：从电话会提取能证明或推翻原论点的回答，并注明谁说、何时说。
- 分析 4：解释价格反应与基本面变化是否一致，更新催化剂、风险和行动条件。
- 输出：财报后差异卡、更新后的价值区间与 BUY/SELL/WATCH；所有改判回链到财报前版本。
- 失败：无电话会时明确 `transcript not available`；官方数与聚合数冲突时 `needs_review`，不选方便的数字。
- 来源与复用：`earnings-deep-dive` 的 actual-vs-bar、EPS quality、debate map；妙想公告/结构化数据路由；复用分析骨架，不复用未验证数据权限。

### S5 供应链早期线索卡

- 支柱：产业链发现；触发：产品架构变化、资本开支、价格/库存/交期异常、送样认证、招标或客户披露出现新信号。
- 输入：一个明确主题、时间窗、需求指标、产业链身份、公司/行业原文与量价序列。
- 程序任务：解析统一行业与证券 ID；建立系统→部件→材料/工艺→供应商关系；记录每条边的证据和成熟度。
- 分析 1：定义需求冲击来自哪里、单位需求如何变化、什么指标能最早观察。
- 分析 2：找可能瓶颈，依次检查产能、利用率、良率、交期、认证和替代路径。
- 分析 3：把候选公司分为研发、送样、认证、订单、交付、收入确认，不跨阶段推断。
- 分析 4：列一名最可能受益者、一名反例和下一条信息价值最高的证据。
- 输出：早期线索卡，含成熟度、领先指标、候选、最大不确定性、下一验证点；此阶段不出目标价。
- 失败：找不到公司暴露时允许“主题成立，暂无可投资受益者”；图谱空结果只表示当前覆盖缺口。
- 来源与复用：同舟 `resolve_research_identity`、产业链图谱和因子面板；妙想 `mx_macro_data`；复用实体/图谱/量价路线，不把供应商名单当订单。

### S6 单票因子最小实验

- 支柱：单票因子；触发：用户提出明确交易问题，或每周研究队列选中一个待验证问题。
- 输入：一只股票、要改善的决定、冻结的持有期/基准/成本/样本、1–2 个事前可知变量、数据版本。
- 程序任务：按 `known_at` 生成特征；信号延迟到下一可成交时点；滚动样本外验证、成本压力测试并保存全部尝试。
- 分析 1：先写变量为何可能影响该决定，以及在哪种市场状态应失效。
- 分析 2：解释样本外相对基线的收益分布、回撤、覆盖/弃权率和换手变化。
- 分析 3：检查结果是否集中在单一时期、财报事件或少数离群样本。
- 分析 4：只判为描述、探索、样本外支持或前瞻验证，不把指标值直接变成买卖命令。
- 输出：因子卡，含公式版本、当前分位、期限、样本外增量、成本敏感度、适用/失效状态。
- 失败：样本不足或 PIT 不合格时输出“未发现稳定增量/不可检验”，这仍是完成，不是 `WATCH`。
- 来源与复用：主架构单票实验协议；本地 `stock-analysis` 的分维度对象可借字段；明确弃用 ±0.33 阈值、绝对分数 confidence 和缺维度后重归一权重。

## 三、后续 6 个场景

### S7 供应链线索转投资候选

- 支柱：产业链发现；触发：S5 候选到达认证/订单/交付阶段，或出现可核实公司暴露。
- 输入：线索卡、客户/产品/产能证据、公司分部数据、份额与毛利假设、资本开支、当前市值与净债务。
- 程序任务：建立销量×份额×单价×毛利的利润桥；做摊薄、现金跑道、估值敏感性和反推市场隐含假设。
- 分析 1：验证公司确实捕获价值，而不只是身处热门行业。
- 分析 2：比较扩产速度、竞争替代、价格传导与客户集中风险。
- 分析 3：按公司阶段选择估值；证据只到认证时用里程碑/反推，不套成熟公司 PE。
- 分析 4：给进入投资池、继续观察或淘汰，并写证伪与催化剂。
- 输出：投资候选卡、价值区间/尚不可估值、最高买入价条件、被淘汰原因。
- 失败：利润桥缺关键变量时停在观察池，不用行业 TAM 按比例映射公司收入。
- 来源与复用：同舟产业链/分析师观点、妙想行业量价与公告；`comps-valuation`、`scenario-sensitivity-generator`；复用同阶段可比和情景法。

### S8 宏观冲击到持仓传导

- 支柱：持仓/自选；触发：利率、通胀、汇率、关税、商品或监管出现超预期变化。
- 输入：官方实际/预期/前值、发布时间、资产反应、持仓暴露、公司成本/收入币种和敏感性。
- 程序任务：计算 surprise、利率/汇率/商品变动及持仓暴露；把宏观事件与公司事件分开。
- 分析 1：画政策/数据→需求或成本→盈利→估值的传导链。
- 分析 2：区分一阶受益/受损、二阶竞争影响和已计价程度。
- 分析 3：比较实际市场反应与通常模式，标 amplified/dampened/inverse。
- 分析 4：只在公司敏感性和时点证据足够时改行动，否则新增监控条件。
- 输出：宏观影响卡、受影响持仓排序、需要重跑的估值变量与下一宏观节点。
- 失败：只有新闻标题或无法量化暴露时不改目标价；宏观“利好”不能自动转为个股 BUY。
- 来源与复用：`macro-monitor` 的实际/预期/前值采集；`market-news-analyst` 的跨资产反应；`economic-impact-report` 的传导框架；不复用固定 24 小时和全市场长报表。

### S9 论点跟踪与反证升级

- 支柱：三个支柱共享；触发：任何关键证据到期、命中 prove/kill 条件或每周复核。
- 输入：冻结的论点、稳定 catalyst/source ID、支持/反驳证据、当前状态、下一检查日。
- 程序任务：仅追加版本；检测过期证据、重复来源、未完成检查和 kill 条件命中。
- 分析 1：逐条把论点状态改为 strengthened/weakened/unchanged/killed。
- 分析 2：说明变化来自事实、预期、价格还是原假设错误。
- 分析 3：若 killed，禁止用正动量抵消；若 strengthened，仍检查估值是否已充分计价。
- 输出：论点差异、改判建议、未解问题、下一证据和负责人。
- 失败：原始判断或当时输入找不到时 `needs_review`，不得从今天的材料重建过去观点。
- 来源与复用：`thesis-tracker` 的稳定 ID、prove/kill 与 cadence；复用版本纪律，权威记忆落台账而非 Bot 自由记忆。

### S10 60/90 日催化剂日历

- 支柱：持仓/自选；触发：新增持仓/观察股、每周刷新、事件日期变化。
- 输入：公司/监管/交易所/行业事件、日期证据、论点相关性、准备动作。
- 程序任务：确认日期、窗口和来源；精确日期才进日历，推定窗口留在跟踪表；刷新时保留旧行和变更记录。
- 分析 1：按能否改变盈利预期、叙事、估值、下行或流动性排序，而非仅按临近程度。
- 分析 2：为高压事件写事前问题、所需模型更新和决策门槛。
- 分析 3：合并同一窗口风险，标出财报、监管、解禁/回购窗口与指数调整的交互。
- 输出：30/60/90 日事件表、时间置信度、准备队列和行动含义。
- 失败：推定日期不生成精确提醒；来源冲突时保留区间并等待官方确认。
- 来源与复用：`earnings-tracker` 的日历思想；`catalyst-calendar` 的 confirmed/windowed、decision pressure 和非破坏刷新；不声称本地 cron 已运行。

### S11 估值与理想价位刷新

- 支柱：持仓/自选；触发：财报后、关键假设改变、股价跨区间或用户问理想价位。
- 输入：业务阶段、历史与预测驱动、净债务/股本、资本成本、同阶段可比、用户持有期与所需回报（如有）。
- 程序任务：执行 DCF/可比/中周期/概率加权模型；统一币种、股本和估值日期；输出敏感性而非单点。
- 分析 1：选择与公司阶段匹配的主方法和交叉检查方法，并说明为什么。
- 分析 2：解释市场当前价隐含的增长、利润率或成功概率。
- 分析 3：区分公允价值、含安全边际买入上限、减仓/退出条件和技术位置。
- 分析 4：检查情景概率、终值、周期峰值利润和可比公司差异是否过度乐观。
- 输出：悲观/基准/乐观区间、关键敏感变量、最高买入价、减仓/退出条件。
- 失败：缺预测、净债务或股本口径时不给伪目标价；仅展示反推“当前价要求什么”。
- 来源与复用：`comps-valuation`、`scenario-sensitivity-generator`、必要时 DCF；`stock-analyzer` 仅借来源状态展示，弃用当前价打折 2%–5% 和买入价固定止损等机械规则。

### S12 决策复盘与经验候选

- 支柱：记忆；触发：决策后 5/20/60 个交易日、论点事件结束或退出后。
- 输入：不可改写的原判断、当时证据包、用户实际决定、后续价格/事件、交易成本和新信息到达时间。
- 程序任务：先隐藏结果生成过程评分，再揭示结果；计算相对基准表现；把建议与实际交易分开。
- 分析 1：评价当时过程是否正确：数据、逻辑、估值、时点、组合约束分别打标。
- 分析 2：再看结果，区分“好过程坏结果”和“坏过程好运气”。
- 分析 3：归因错误来自未知事件、证据遗漏、口径、过度外推、估值或执行。
- 分析 4：只生成带样本、适用条件和反例的候选规则；未经后续样本与人工审阅不得改 skill。
- 输出：复盘卡、错误分类、候选经验、需要新增的测试用例；保留原判断链接。
- 失败：历史 `known_at` 无法恢复时只做运行质量复盘，不做无泄漏的投资能力结论。
- 来源与复用：主架构历史台账；`thesis-tracker` 的状态历史；复用审计与复盘，不让模型记忆充当行情、持仓或历史判断真相。

## 四、发布顺序与验收

首发按 S1→S2→S3/S4→S5→S6 推进。S1、S2 先用一只持仓和一只自选连续跑 5 个交易日；S3/S4 用一次真实财报完成前后闭环；S5 用一个主题、2–3 个候选和至少一个反例；S6 只验证一个交易问题和 1–2 个变量。

后续再上 S7–S12：先把早期线索转投资候选，再扩宏观传导、论点日历、估值刷新与复盘记忆。它们共享首发已验证的实体、证据、任务、判断版本和失败状态，不另建一套 agent 体系。

每个场景的验收都看五件事：相同输入能否复现；关键数字能否回链；空数据是否被误写为中性；时间/币种/单位是否一致；同一业务键重跑是否不重复发布。金融结论质量再看是否找到原先遗漏的关键证据、真正反证和可执行转判条件，不能用报告长度或多个 Bot 一致作为通过标准。
