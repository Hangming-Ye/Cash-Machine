# Bot 工作方法与交接契约（P-03）

面向现有 Bot 的配置，不是平台内部 system prompt。复用现有名单和 Routine；岗位职责可以合并，同一 Bot 可执行多个方法，不固定岗位数量。

## 三个原生入口

| 入口 | 配置内容 | 读取方式 |
| --- | --- | --- |
| 用户聊天 | 目标、范围、期限或更新请求；长期职责放 Description | 指向研究 Skill，任务前读取对应主题和经验 |
| 现有 Routine | 触发约定、范围、研究 Skill 名及工作区位置 | 每轮重新读当前摘要与数据，不假定继承上一轮上下文 |
| 专员交接 | 当前问题、关键材料、已有发现、反证、交付要求 | 原生消息给短摘要和具体文件定位，不假定继承父会话 |

不建立 Bot 生命周期 API、完成回调、心跳轮询或 pre-call hook。文件读取行为与实际研究效果需原生产品验收。

## 一份任务说明

至少包括：本轮 question；用户允许的 scope；研究 horizon 和 as_of；证券或主题身份；可用材料的路径／出处；相关记忆包；要执行的分析步骤；交付内容；关键证据不足如何补证。没有研究期限时优先沿用该委托已有约定；确实影响问题意义且不能推断再问，不把非必要参数补齐变成启动障碍。

交接只需 request_id、问题、短上下文、输入路径和预期结果位置。独立专员各写自己的产物，负责该轮汇总的 Bot 阅读并合成。原生消息没返回时可以查询已有产物或简单重问，不建设任务状态协议。

## 方法覆盖

| 方法 | 必做工作 | 可交付结果 |
| --- | --- | --- |
| 供应链探索 | 需求变化→系统与环节→瓶颈／替代→公司暴露→兑现→估值→反证 | 候选及证据，或排除原因；后续验证点 |
| 公司／持仓分析 | 只读持仓与行情时点→经营与财务→行业／事件／情绪→估值与条件→冲突解释 | buy／sell／watch 与期限、区间或条件、风险及失效点 |
| 单票因子 | 经济假设→已可得字段与组合→冻结验证请求→程序计算→解释增量与失败情形 | 已验证支持、仅描述／探索或无增量；不能伪造实验 |
| 来源补证 | 定位关键缺口→已有来源与网页／原披露→保留原文定位及口径→限定受影响结论 | 补充证据和缺口记录 |
| 复盘与记忆 | 原判断对照后续事实→归因→有条件教训→去重压缩→主题／经验回写 | 更新摘要、经验、反证及下一次检查项 |
| 复核 | 关键主张回查来源、计算口径、对立解释、遗漏与结论适用性 | 需修正项及理由，不用意见投票代替证据 |

这些是可组合方法，不限制用户只能提出表中标题。研究中出现新的合理问题可以组合继续，确需越过用户范围时再请求取舍。数据缺口与工具能力缺陷分开记录。

## 交付

Bot 先生成草稿，再显式调用 `check artifact --archive` 固化 Decision／WorkRecord／Review；得到记录 ID 后再交付历史引用或调用 memory apply，失败时不能声称已归档。

报告至少包含：结论与有效期限、依据、价格／条件（适用时）、反证与风险、资料缺口、下一步；附证据与计算产物定位。标注事实、第三方观点与我方假设。手机和 PC 使用同一份结果。相应记录保存本次使用的记忆及采用／拒绝理由，详尽清单可在附件，不强迫主报告展示工程字段。

一次复核发现重要问题就针对性补证或修正，未解决则保留限制；不设置反复辩论循环或固定“所有研究最多两项补证”规则。失败说明可重跑的具体输入，重跑不覆盖旧判断。通知机制不在此契约。

## 旧 bot-kit 的迁移

保留有用的研究步骤与反证要求；删除固定流程白名单、固定候选数、每个新公式退开发、固定一轮修正／两项补证等未被确认限制。删除自建状态机、交付通知状态、调度命令及底层 system prompt 控制承诺。实施时再改写实际文本，本轮不把旧文件标为可直接部署的最终版本。

迁移对象使用实际路径：bot-kit/prompts/common.md、chief.md、research.md、market.md、quant.md、reviewer.md。实施时逐一改写或明确停用，并更新 bot-kit/README.md 的加载清单；不另建 roles/ 目录或第二份 common.md。部署核对真正加载的岗位／Skill 版本，旧固定流程、逐公式注册和两项补证上限不得残留生效。
