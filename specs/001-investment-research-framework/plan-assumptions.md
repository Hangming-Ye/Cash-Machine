## 本轮新增

| ID | 拟采用的假设／技术选择 | 为什么增加 | 影响／代价及替代方案 |
| --- | --- | --- | --- |
| P-01 | Python 3.12 + 一个按需 CLI／包；uv 管理；数值用 pandas／NumPy／SciPy，契约用 Pydantic，HTTP 用 httpx；保留现有源所需 SDK | 统一可复查取数、计算与文件校验，避免多个常驻服务 | 新工程需要部署依赖；可改为云端已有兼容 Python 版本，但本计划先按 3.12 设计。没有安装或替换运行环境 |
| P-02 | 共享 `/workspace/cash-machine/` 私有文件目录，JSON／CSV／Markdown；初版不建数据库服务或独立 UI | 与 Bot 文件／终端入口一致，易读易查，减少运维 | 大规模历史数据检索可能需升级；路径可配置，保留原始材料会增加磁盘占用 |
| P-03 | 不固定新 Bot 数量，将现有 Bot 映射到职责；方法写 Skill，Routine 仅触发；不建立任务调度状态机 | 保留现有使用方式，并补足专员任务方法 | 仍依赖 Bot 执行读写指令；先留私有 Bot／Routine 映射，须在新会话／临时且禁用计划的测试 Routine／交接三入口验证，不能靠底层 hook 强制执行 |
| P-04 | 新增统一来源／证据记录及少量按需 CLI 接口，网页材料通过导入保留出处；调用结果分类，不建立任务状态协议 | 避免旧映射丢时点、来源和部分失败，支撑补证和复盘 | 需要重映射现有接口字段；先查三市场覆盖，必要时导入已有带来源的完整历史文件，仍缺数据则提前报告验收受阻；不能原封不动使用旧 Client 输出。供应商名单本身不是新增假设 |
| P-05 | 因子采用“命名运算的结构化组合”，允许新公式与参数；粒度参数化、日频先验证、时间隔离、试验记录，不执行模型自由生成代码 | 解决每个新因子都退开发与弱模型任意写代码两个问题 | 需实现薄表达式解释与校验；非日频可用同一运算但须有合格数据；订单簿／新统计原语等新能力仍需扩展。日频优先仅为验证顺序，不限制调用范围 |
| P-06 | 估值首批支持 DCF、可比倍数、EV—权益桥、分部／资产法；模型给有依据假设，程序算情景与敏感性 | 让理想价位可复查，而非心算或固定折价 | 不保证每种公司都适合数值估值；方法不适用时给条件。新增公式由同一计算模块扩展 |
| P-07 | 记忆优先使用主题／证券／方法索引与文件，提炼由现有 Bot 执行；暂不安装 Mem0／LangMem／Letta，检索失效再对比组件 | 适应有限自定义产品，减少第二套模型服务和存储依赖 | 初版跨措辞召回可能弱，必须用样例验证；材料预算按可读性测试配置，不宣称控制原生上下文 |
| P-08 | 每主题一个现有写入负责人；专员各写材料，摘要更新带版本，保留旧版并做一次文件写入的串行检查／原子替换 | 避免并发静默覆盖，同时保留记忆压缩能力 | 增加薄版本检查与合并重试；不引入任务锁平台、租约或后台恢复。无需每条经验用户审批 |
| P-09 | 实施切片按原生入口样例→数据／持仓→供应链／估值→因子→全量记忆与跨市场验收；记忆读写从首个研究切片就接入 | 尽早验证产品入口，避免末期才发现无法注入 | 这是开发顺序，不删减三类目标；运行数据缺口不能以受限报告充当最终验收完成 |
