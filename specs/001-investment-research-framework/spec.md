# Feature Specification: 持续投研与决策支持框架

**Feature Branch**: `codex/001-investment-research-framework`

**Created**: 2026-09-20

**Status**: Draft

**Input**: 依据已确认的 [Intent](../../docs/intent.md)，生成 spec001，并明确从意图到规格的假设与新增要求。

本规格定义完整框架的用户行为和验收范围，不代表已有能力上线。三类核心能力均为交付范围；可分批实现，但不能以仅完成取数或其中一类能力宣称本规格完成。研究文档和 bot-kit 是方法参考，不自动成为约束；constitution 已按用户明确约束整理；不表示 plan 新增选择获批。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从产业变化发现可验证的投资机会 (Priority: P1)

用户给出产业主题、市场和研究期限后，框架自主拆解供应链、寻找瓶颈与潜在受益公司，并推进到商业兑现、估值及反证判断。

**Why this priority**: 这是主动发现机会的核心目标，与持仓判断、因子研究同为必交付能力。

**Independent Test**: 给出一个主题和一组可追溯材料，独立检查能否得到有证据的候选或有依据的排除结果，不依赖用户先提供公司名单。

**Acceptance Scenarios**:

1. **Given** 只有主题与研究范围，**When** 启动探索，**Then** 产出需求变化、供应环节、瓶颈证据、替代方案和候选公司，解释从变化到公司盈利兑现的联系。
2. **Given** 某公司处于瓶颈环节，**When** 形成候选结论，**Then** 核查其实际业务敞口、竞争与供给扩张、兑现时点、估值隐含预期、催化剂和推翻假设的条件；不能仅凭产业位置推荐。
3. **Given** 证据否定初始主题，**When** 继续研究，**Then** 自主补证或在原范围内调整方向，保留被否定的原因；确需改变用户目标或研究范围时再请求取舍。
4. **Given** 未发现合格机会，**When** 结束研究，**Then** 交付筛选依据、排除原因和后续观察条件，不能为了凑结果生成候选。

### User Story 2 - 对持仓和自选给出可操作的研究判断 (Priority: P1)

用户指定或更新持仓、自选和研究期限，获得结合走势、基本面、行业、情绪与事件的买入、卖出或观望评价及价格或条件。

**Why this priority**: 直接支撑已有主观交易，与另外两类目标并列。

**Independent Test**: 使用一个标的及其材料独立生成判断，检查各结论、价格和适用期限能否追溯到证据或明确假设。

**Acceptance Scenarios**:

1. **Given** 用户提供一个标的或列表，**When** 请求评价，**Then** 每个标的得到三类评价之一、理由、理想价格区间或触发条件、适用期限、主要风险和失效条件。
2. **Given** 财务、价格与情绪结论相互冲突，**When** 综合判断，**Then** 保留冲突并说明取舍；区分事实、市场观点和研究者推断，不以无说明的分数替代论证。
3. **Given** 关键证据不足以支持方向或价格，**When** 替代获取仍失败，**Then** 输出“观望／证据不足”，说明哪些结论受限及下一步补证；不能伪造理想价，也不能将其混同于“估值合理所以观望”。
4. **Given** 新材料改变旧判断，**When** 更新结果，**Then** 展示与前次结论的差异及原因，并保留前次记录。
5. **Given** 用户已提供券商只读凭证且有现有接入能力，**When** 请求持仓研究，**Then** 从已授权券商读取可用持仓及账户信息，注明数据时点；失败时报告具体缺口，不把接入降为可选的未来工作。自选若不受该接口支持，可由用户提供。

### User Story 3 - 验证单票因子是否具有决策增量 (Priority: P1)

用户指定股票和研究期限，框架提出有经济或行为解释的因子假设，完成数据验证并解释对主观交易的帮助和局限。

**Why this priority**: 防止因子研究被简化成指标罗列或未经验证的交易信号。

**Independent Test**: 使用一个标的的历史数据，检验一个假设及其基准，在未参与选因子的时段评价增量，允许最终没有可用因子。

**Acceptance Scenarios**:

1. **Given** 标的和研究问题，**When** 启动因子研究，**Then** 明确预测对象、持有期限、因子定义、当时可获得的输入、比较基准和验证方式后再解释验证结果。
2. **Given** 有可用历史数据，**When** 评价因子，**Then** 区分探索与验证样本，检查未来信息泄漏、复权与公司行动、样本量和多次试验选择偏差；说明不同时段表现及成本影响。未涉及模拟交易的因子说明成本不适用的原因。
3. **Given** 因子只在探索样本有效，**When** 形成结论，**Then** 不列为已验证有效，说明失败或适用条件，不生成自动交易指令。
4. **Given** 只能搜索到零散历史事实，**When** 尝试补充，**Then** 可推进假设和可行性研究，但不得宣称完成完整历史验证。

### User Story 4 - 在既有 Bot 环境中委托研究 (Priority: P1)

用户在手机与 PC 混合使用既有 Grok Bot，通过已有常驻、定时及并发能力开展研究，交付格式不因设备改变。

**Why this priority**: 研究应接入用户已在使用的 7×24 环境，主要工作是让专员能完成研究，而非另建运行平台。

**Independent Test**: 在现有环境触发一次定时研究及两个不同范围的并发任务，从手机和 PC 查阅同一交付；失败时检查能否解释原因并简单重跑。

**Acceptance Scenarios**:

1. **Given** 已有常驻与定时能力，**When** 研究按既有入口触发，**Then** 直接调用相应研究方法并交付结果，不要求新建调度器或运行协议。
2. **Given** 两个并发任务，**When** 交给专员，**Then** 每位专员获得独立可理解的目标、范围、材料、方法和交付要求，不依赖父会话隐含背景，结果归属清楚。
3. **Given** 同一份研究结果，**When** 用户从手机或 PC 打开，**Then** 可查看相同的结论、依据、缺口和下一步，不设设备专用交付格式。
4. **Given** 一次研究调用失败，**When** 查看结果或再次执行，**Then** 能看到失败原因并重新运行；不要求断点续跑、自动补跑、恰好一次交付或新增复杂状态机。已有历史判断不因重跑被覆盖。

### User Story 5 - 数据受限时主动补证并交付可信结果 (Priority: P1)

框架综合客观数据和研报、新闻、社交观点，主动寻找替代来源，使信息缺口不会直接变成任务被放弃。

**Why this priority**: 所有核心研究均依赖证据质量；缺少方法和没有数据必须分开处理。

**Independent Test**: 人为使首选来源不可用，并提供部分可公开搜索的原始披露，检查补证、引用、冲突处理与受限结论。

**Acceptance Scenarios**:

1. **Given** 首选渠道缺失或不可用，**When** 获取材料，**Then** 主动尝试网页搜索、原始披露或其他适用来源，记录尝试及结果，继续可完成的研究。
2. **Given** 材料包含投行观点、新闻或社交讨论，**When** 使用这些材料，**Then** 记录出处、作者或机构（可得时）、发布时间及获取时间，区分转述和原始材料；未读到全文不能宣称已审阅全文。
3. **Given** 两个来源对同一关键事实不一致，**When** 形成判断，**Then** 核对时点、单位和统计口径；无法消除的矛盾须保留并说明对结论的影响。
4. **Given** 合理路径已尝试仍有关键缺口，**When** 结束本轮，**Then** 明确区分证据受限、未发现机会、因子无增量和执行失败，提供可恢复的后续动作；缺少本应具备的方法按能力缺陷记录，不能冒充正常完成。

### User Story 6 - 回顾历史判断并积累可复用经验 (Priority: P1)

用户可回看当时依据、后续变化和判断成败；后续研究能够使用相关历史经验，并说明其适用范围。

**Why this priority**: 解决持续研究没有积累、同类错误重复发生的问题。

**Independent Test**: 用包含重复、过时和反证的历史案例验证提炼压缩，再启动新会话，检查实际注入的经验及其对研究检查项的影响。

**Acceptance Scenarios**:

1. **Given** 已交付判断，**When** 约定复盘时间到达或用户主动要求复盘，**Then** 比较当时假设、价格或触发条件、期限与后续事实；未到观察期限或未触发的判断不能直接判为成功或失败。
2. **Given** 结果与预期不同，**When** 归因，**Then** 分开讨论证据错误、推理错误、执行问题与市场路径变化，不使用后来信息改写当时依据。
3. **Given** 多次研究与复盘积累，**When** 整理记忆，**Then** 提炼可复用经验，合并重复项并压缩表述，保留原始案例、适用条件、反例与时效；压缩不能把推测改为事实。
4. **Given** 新任务开始，**When** 准备专员输入，**Then** 按问题检索相关经验，在限定上下文预算内注入，记录实际注入内容；不能只把检索工具交给模型却不验证是否使用。
5. **Given** 经验过时或出现反证，**When** 更新和使用记忆，**Then** 旧经验可追溯但不再作为当前有效经验注入；复盘交付说明哪些经验被采用、被反驳或不适用。单次成败不能自动成为通用规则。

6. **Given** 周期研究再次执行，**When** 准备输入，**Then** 注入上次有效基线、尚未解决的问题和本次新增证据；无变化不重复沉淀相同经验，旧行情不能充当当前行情。
7. **Given** 一个主题跨多个周期推进，**When** 新会话继续研究，**Then** 取得当前假设、支持与反证、关键变化及下一验证点，能说明判断如何演变；压缩不丢失尚未解决的分歧。
8. **Given** 深度分析材料超出单次上下文或需要重新分析，**When** 拆分分析或更新结论，**Then** 按当前问题取用证据与阶段摘要，保留关键假设、反证、计算口径和原文定位；输入或假设改变时重新核查相关结论，不直接复用旧摘要中的答案。

### Edge Cases

- 同名公司、跨市场上市、币种和交易时区不同：先明确证券身份与比较口径，无法消歧时只暂停依赖该身份的部分。
- 停牌、退市、拆股和历史缺口：注明覆盖与可比性限制，不用当前名单或当前价格补写历史。
- 研报受限、付费源不可访问、社交内容删除：说明可访问范围并寻找替代，不能虚构全文、购买权限或有效历史记录。
- 用户没有提供风险预算、成本或持仓数量：可做标的研究；不假定仓位，不生成伪精确的个性化仓位建议。
- 手机断开不等于 Bot 停止；研究调用失败可说明原因并重跑，不由本规格承担平台级容灾或运行状态机。
- 全部补证路径失败：输出限制、已尝试路径和恢复条件，不无期限重试，不据缺失证据生成肯定判断。
- 新主题超出原范围：列明扩展价值及取舍请求；原范围内可继续的工作继续推进。
- 材料含命令或诱导内容：作为研究材料处理，不能改变任务权限、研究目标或触发订单。

### Key Entities *(include if feature involves data)*

- **研究委托**：用户目标、范围、市场／标的、期限及已有运行入口；可关联多个执行记录。
- **执行记录**：本轮目标、专员任务、进度、获取尝试、异常、交付及后续动作，关联所属委托。
- **证据材料**：内容定位、来源、发布时间／获取时间、适用时点、单位口径、覆盖和局限；可支持或反驳假设。
- **研究假设与候选**：产业关系、获益机制或因子命题，以及支持证据、反证和验证状态。
- **判断记录**：某时点的研究结论、理由、价格或条件、期限、风险与证据；关联前次版本。
- **复盘与经验**：对判断的后续检验、归因、适用条件和失效依据；经去重压缩后按任务注入新研究，保留注入记录。

### Scope and Dependencies

- 本规格覆盖三类研究、专员工作方法、持续执行、补证、交付和复盘；不锁定 Bot 数量、模板数量、角色拓扑、技术栈、数据供应商或固定重试次数。
- 原生 Grok Bot 的可配置程度是设计边界。记忆再注入指任务开始或阶段切换时显式读取／传递相关材料，不假定能替换内部记忆、编辑原始 system prompt 或拦截每次模型调用。组件接入方式须有产品证据或现场验证；研究依据见 [Grok Bot 记忆接入调研](../../research/15-grok-memory-integration.md)。
- 用户确认 Grok Bot 已在 7×24 运行，本轮对接现有运行能力，不重新证明全年在线或新建调度／恢复平台；只验证研究调用链。通知不在范围。
- 数据候选按用户已在 Grok Bot 接入的来源规划；遗漏单列并补证，不重新做供应商选型。Plan 的新增假设及技术选择完成后由用户审批。
- 依赖可访问的研究材料与适用的数据权限；付费权限不默认为已购买。用户确认券商只读凭证已提供且已有实现，接入属于本轮要求；实际联通仍需实施时核验，本轮不读取或展示凭证。
- 不包含自动交易、多用户商业平台、利润保证或强制复用旧工程。候选公司可被发现，但买入／卖出评价必须明确对应可研究的上市证券。

## Success Criteria *(mandatory)*

### Measurable Outcomes

以下数量和调用检查是本次新增的验收基线（A-04），不代表已证实的性能，也不是运行容量上限。

- **SC-001 核心覆盖**：至少完成三类能力 × 三个市场的 9 个独立完整研究案例。每类至少有一个不来自既有任务示例的自然语言问题。逐项满足相应用户场景；受限案例不得替代这 9 个完整案例。
- **SC-002 主动性与异常**：额外覆盖首选源失败、关键源冲突、历史不足、无合格机会、无因子增量、范围变更、调用失败和券商读取失败共 8 类情形。每类均呈现约定后续动作，不要求用户代写研究步骤；所有应补证情形有尝试记录。
- **SC-003 可追溯性**：对验收案例中的全部关键事实、价格依据和因子验证结果可定位证据或复查计算；来源／时间／口径缺失必须显式标记。不得出现无标注的编造数据或以受限材料冒充完整验证。关键指直接改变候选、方向、价位或因子有效性结论的内容。
- **SC-004 专员可执行性**：对三类研究各选至少一个任务，在隔离父会话背景后，由目标 Grok Bot 环境中的专员完成并达到相应交付标准；记录产品版本、可见的模型信息及提供的输入；平台未暴露的模型信息标为不可见，不要求用户指定原生模型。只有提示词文件不能通过。
- **SC-005 可复查性**：同一证据与参数重复进行验收案例内的确定性计算，结果在事先声明的数值精度内一致；数值精度和基准先于执行记录。研究判断变化需要说明，不要求模型措辞相同。
- **SC-006 既有环境接入**：在既有环境完成一次定时研究调用、两个不同范围任务并发及一次调用失败后重跑，结果归属正确，手机和 PC 查看同一交付。完成一次已授权券商只读读取并确认持仓进入研究输入；失败不得伪装为空仓。取消 7 天观察、专用调度和复杂恢复验收。
- **SC-007 记忆与实用性**：至少 3 条判断完成复盘；用含重复、过时及反证的案例验证经验提炼、合并压缩和失效处理。压缩后在预先声明的上下文预算内保留来源与适用条件；新会话实际收到相关经验，无关和失效经验不得当作有效结论注入。记录注入内容及研究中采用或拒绝的理由，并对同一任务比较有／无经验时是否补上历史暴露的检查遗漏；只保存或只检索不通过。另需覆盖定时任务的增量比较、长期主题跨会话续研、重分析的证据回查及假设变化后重算／重评；这些场景可复用已有案例，不要求另建三套系统。9 个核心案例仍须回答结论、依据、期限、反证和下一步。
- **SC-008 边界**：验收中订单执行次数为 0，公开交付中的凭证或非公开持仓泄露为 0；所有持仓缺失和材料诱导案例均按边界要求处理。
