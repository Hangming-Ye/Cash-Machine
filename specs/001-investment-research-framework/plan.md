## Summary

在已有 Grok Bot 上配置清晰的研究方法，由原生聊天、Routine 和 Bot 协作触发。以共享工作文件衔接研究和记忆，以一个按需运行的 Python 工具包处理取数、计算、材料筛选和结构校验。交付仍在原生会话中呈现，不增加独立网页、通知系统、后台调度或第二套 Agent 平台。

数据来源沿用 Finnhub、Tiingo、FMP stable、AKShare、IBKR Flex 和长桥只读能力。以用户确认和 handoff 为接入基线，以旧代码审阅说明字段限制；不将本地代码快照的缺失等同于云端没有功能。具体遗漏与处理见 [数据基线与缺口](data-sources.md)。

三类研究均交付：供应链研究通过证据链发现及验证公司；持仓研究结合实时点清晰的账户／行情和基本面形成价格或条件；因子研究以可组合计算和时间隔离验证探索假设。记忆完成读取、研究、提炼压缩和回写，按定时、长期、重分析特点选取内容。

## Technical Context

**Language/Version**: 拟定 Python 3.12（P-01）；以 uv 管理新工程与锁文件。部署前检查云电脑运行环境，不继承旧工程依赖锁。

**Primary Dependencies**: pandas、NumPy、SciPy、Pydantic、httpx；AKShare／长桥 SDK 仅用于对应现有适配器；IBKR Flex 用 HTTP/XML。开发验证用 pytest。版本由实现时兼容性检查及 uv.lock 固定；本轮未安装。暂不加入向量数据库、Mem0、LangGraph、Letta、Web 服务框架或新数据服务。

**Storage**: 共享 `/workspace/cash-machine/`（路径默认值，可配置，P-02）中的 JSON、CSV、Markdown 与原始附件；配置／程序／运行数据分开。无常驻数据库服务。精确数值采用带币种与单位的表示；计算数据采用明确精度并记录处理方式。

**Testing**: 契约与数值单元检查、冻结样例集成检查、现有数据源只读实测、原生 Grok 任务行为验证分层执行；不以 API 模型测试替代 Bot 实测。

**Target Platform**: 当前用户的 Grok Bot 共享云电脑；手机与 PC 是同一结果入口。Windows 工作区负责开发和文档，部署不依赖本机保持在线。

**Project Type**: Bot 配置／Skills + 可导入 Python 包与 CLI。新包名拟为 `cash_research`，命令为 `cash-research`；名称是 P-01 的技术选择。

**Performance Goals**: 按 spec 的完整研究、可追溯与记忆使用标准验收；同输入确定性计算可复查。任务体量与外部来源耗时差异大，不承诺统一报告秒数。记录取数、计算、模型研究和记忆整理的耗时；记忆返回材料预算单独约束，不宣称控制原生总上下文。

**Constraints**: 原生 Description／Skill／Routine／文件／终端入口；不假设 Bot 管理 API、内部 system prompt 或 pre-call hook。仅只读券商权限；通知不在范围；市场与范围运行时指定；不得因范围开放而执行任意模型代码。

**Scale/Scope**: 当前用户、多 Bot、三市场、三类研究；不固定股票数或研究主题上限。分批取数与计算资源上限属于运行参数，不缩小研究范围。本文件 P-01—P-09 已批准；tasks 新增拆分决定另行说明。

## Research and Design Decisions

完整 Decision／Rationale／Alternatives 见 [research.md](research.md)。

### 1. Bot 的职责与任务展开（P-03）

先在私有工作区记录现有 Bot／Routine 名称、方法入口、资料路径与当前职责，形成 bot-mapping.json；不把账户标识或生产配置写入 Git。保留现有 Bot 名单，配置时将其映射到协调、公司／产业、市场／事件、量化、复核等职责；这些不是强制新增五个 Bot。迁移以 bot-kit/prompts/ 的 common、chief、research、market、quant、reviewer 为实际源，逐一改写或停用并更新加载清单，避免新旧指令同时生效。岗位只保留职责、方法入口及边界，具体任务提供目标、范围、材料、问题和预期交付。

协调者从用户目标整理当前问题，选择并组合研究方法。阶段可以迭代补证、增加范围内候选，不设置固定工作流白名单或永久的候选数量上限。独立问题通过原生消息并发；相依分析按依赖顺序做。以问题和材料交接，不引入节点状态数据库。计算程序不驱动 Bot，也不创建／轮询 Routine。

任务交接、失败重跑及交付契约见 [bot-workflow.md](contracts/bot-workflow.md)。复杂性约束不等于让弱模型自由猜测：每种研究方法必须明确分析步骤、证据标准和反例检查。

### 2. 从既有来源到研究材料（用户确认，P-04 为细节）

优先调用当前源。保留供应商原始时间、实际来源、复权／修订口径及缺失信息，不让默认值伪装成事实。源不可用时尝试同一已接入组合中适用的路径，再用 Bot 原生网页／浏览器补原始披露与公开材料。

网页得到的数据经材料导入保留 URL、定位、发布时间和可得时间；连续数值序列与零散文本分开使用。研报或社交不能因暂无系统接口而被排除，也不能把新闻改写成研报。补证后仍有缺口，登记具体数据、影响及可继续部分；没有自动采购或新账号开通。

### 3. 供应链与持仓评价

供应链按需求变化、系统环节、瓶颈、替代路径、公司暴露、利润兑现与估值逐步研究，先探索后验证。材料不足可以保留线索，但区分线索与投资候选；反证及下一验证点必须随结论保留。

持仓与自选按证券身份、账户时点、基本面、价格、行业、事件和情绪综合判断。只读账户失败不是空仓。由模型提出有来源的情景假设和合适估值方法，程序计算，模型解释区间及失效条件。拟支持现金流折现、可比倍数、企业价值至股权价值桥、分部／资产法；方法不适用时可输出有依据的里程碑或条件，不能强行算价（P-06）。

### 4. 因子挖掘不等于注册公式查表（P-05）

使用命名数值操作的组合与参数描述，允许在已接入字段上提出新组合，不为每个窗口、阈值或因子组合新增程序。程序解析结构化表达并计算，不使用 eval，也不运行 Bot 临时生成的任意 Python。

时间粒度是实验参数，日频仅为首个验证样例；同一计算引擎可处理已取得且口径一致的其他粒度，来源不支持时报告数据缺口，不以日频作为永久研究边界。每次实验先固定经济假设、数据可得时间、目标、基准、分割、主要指标与成本假设，再计算。探索可据失败修改组合；所有尝试记录，最终留出区不用于选组合；改变方案后不能继续声称原留出区未被见过。所需新运算确超出通用能力时登记精确扩展缺口，继续可检验部分，不将常见任务一律退回开发。

具体运算覆盖、时点规则和实验契约见 [calculations.md](contracts/calculations.md)。这是可配置计算，不是新建通用策略语言或可视化编排器。

### 5. 记忆的实际调用（P-07—P-08）

任务开始由 Skill 要求读取相关摘要和经验；CLI 可按主题／证券／方法与时点筛选，返回一个有限长度的材料包。Bot 通过文件或工具返回值读入，专员交接显式传递必要摘要及来源定位。它不是底层强制注入。记忆请求明确 current／historical／review 模式；历史读取按版本 known_at 和证据 available_at 筛选，复盘将当时输入与后续事实分区，不能因材料早发布就把后来形成的经验倒填到过去。

定时任务读取基线与未决项，更新增量；长期任务更新主题假设与进展；重分析按子问题读取证据、计算依据与阶段产物。原始记录保留，工作摘要可合并更新，经验由已有 Bot 按方法提炼和压缩，再由小程序检查必填字段、出处可定位与预算。语义真伪仍需研究复核，程序检查不冒充语义保证。

每个主题安排一个现有责任 Bot 更新摘要，其他 Bot 提交独立材料；普通读取不加锁。写入带原摘要版本，冲突则回读后重新合并，不自动丢掉任一方成果；仅对该次本地写入串行校验与原子替换，不建队列、租约或任务状态机。初版不引入外部记忆服务或新增专门记忆 Bot。

### 6. 运行与交付

数据、计算和记忆命令按需运行即退出。结果以可读报告、关键数据文件和证据链接保存，原生会话给出同一摘要和产物入口。失败给原因和可重跑输入，判断／执行／复盘草稿通过 check artifact --archive 校验并保存不可变记录，成功返回 ID 后才引用；默认 check artifact 仅检查。已有研究记录保留；无调度补偿、自动恢复协议或通知设计。

源适配与计算确定性校验先做；金融语义检查由承担复核职责的 Bot／用户在验收时对照原文检查。日常研究不要求逐条人工审批；用户所要求的审批对象是本轮新增 plan 选择，不扩成运行期层层审批。

## Delivery and Validation Sequence

顺序是实施切片建议（P-09），全部均须完成，不代表删减目标：

0. **部署清点与数据覆盖前置检查**：记录现有 Bot／Routine 映射，先检查三市场完整案例需要的既有数据，特别是港股历史。允许带来源与时点的已有导出文件／公开完整序列导入；仍不可得则提前报告受阻案例和影响，不等大量实现后才发现，且不擅自新增供应商。
1. **原生调用样例**：用合成资料跑 Skill、共享文件、终端和专员交接；确认实际产品入口，失败调整入口文本。
2. **数据与持仓闭环**：接现有只读源与券商，完成一次有依据的标的评价；材料时间和字段不可用情况明确。
3. **供应链与估值闭环**：自主发现候选、计算适用的估值情景、反证复核；覆盖无合格候选。
4. **因子闭环**：参数／运算组合、历史口径验证、样本隔离、试验记录、无增量结论；验证一个新的合法组合无需开发改码。
5. **记忆与跨入口验收**：此前切片从开始就读写记忆；此阶段集中检查压缩、长期续研、失效和重分析，并完成 spec 的跨市场案例。

测试运行步骤见 [quickstart.md](quickstart.md)。API／数据权限和 Grok 行为属于现场验证项，已有明确操作与失败后处理，不是悬置的架构选型。实施已开始；尚未完成的生产能力及现场验证不得按计划文本宣称已实现。
