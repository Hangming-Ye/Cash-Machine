# 现有数据基线与单列缺口

本 plan 按用户最新指令沿用现有 Grok Bot 接入，不重新选供应商。依据：[handoff](../../HANDOFF_FOR_SENIOR_PLANNER_20260920.md)、[原实现审阅](../../research/13-current-data-implementation.md)、[Intent](../../docs/intent.md)。用户已确认券商只读能力及凭证；本轮未读取秘密内容、未调用账户或金融服务。

## 基线

| 来源 | 当前用途 | 规划处理及已知边界 |
| --- | --- | --- |
| Finnhub | US/HK 报价、公司／市场新闻 | 保留；不根据产品目录推定 candle、目标价或研报权限 |
| Tiingo | US 历史日 K | 保留主源；原映射的 raw OHLC／adjVolume 混用及未保留公司行动需修正 |
| FMP stable | US 公司资料及年报三表 | 保留 stable 接口；保存可获得的披露时间、链接与版本，不能用报告期代替可得时间 |
| AKShare | CN 行情、日线、新闻、部分财报 | 保留现有入口；记录实际底层来源及复权方式，不把缺失时间补成当前时间 |
| IBKR Flex | 账户／持仓／成交只读 | 继续 T+1 路径，保留 Query 数据时点；不引入 Gateway/TWS 实时接入 |
| 长桥 OAuth | 账户／持仓／成交只读 | 继续只读 TradeContext；不扩为行情主源，不调用订单写接口；自选情况单独核验 |

以上证明级别不同：handoff 是现有配置声明，代码审阅是本地快照证据，用户确认定义当前接入要求；它们均不等于本轮 live 验证。现场先确认当前云端已有实现及环境，再决定局部复用或新适配，不用本地归档覆盖云端能力。

网页搜索、公司 IR、交易所／监管披露和用户材料是现有 Bot 补证渠道，不是本轮新增供应商。金融 MCP 未列为已接入能力；不得把研究里出现过的商业服务默认为已购买。

## 缺口与处理

| ID | 遗漏／不确定项 | 当前方案 | 对验收的影响 |
| --- | --- | --- | --- |
| G-01 | 港股连续历史日线未在本地快照确认 | 先核对云端已有源的真实覆盖和权限；有覆盖则接入；已有导出文件或可公开取得的完整序列可经 data ingest 保留来源后导入；仍无则在前置检查报告验收受阻，不新增行情供应商 | 未取得合格序列前不能通过港股因子完整案例 |
| G-02 | 原映射的复权、拆分、分红及股本信息不足 | 提取现有源实际返回字段，保留原始值及调整依据；披露补公司行动 | 无法确定跨期可比性时，受影响收益与因子不作验证结论 |
| G-03 | 财报 PIT、披露／修订链缺失 | 保存现有源字段及原公告版本；历史重建有材料才做，不能事后抓当前修订值充当原值 | 不满足历史可得性时，基本面因子只能保留假设／描述性结果 |
| G-04 | 研报全文及社交观点尚无系统化接入 | 原生搜索／浏览器查公开研报、新闻、社交原帖；可读部分注明范围，保留反方材料 | 可支持具体研究，不宣称有完整研报库／社交历史；来源受限影响相应结论 |
| G-05 | 长桥自选分组：handoff 称有，本地审阅未找到 | 优先核对云端现有能力；若确实缺失允许用户提供自选，账户持仓仍必须接入 | 自选未验证与持仓失败分开，不回退成“券商未来再接” |
| G-06 | 时间、单位、实际底层源、空值／部分成功语义丢失 | 新契约明确保留，适配器逐项映射；不造默认日期或补零 | 关键字段质量不通过时受影响部分受限，记录失败原因为数据或实现 |
| G-07 | 旧 cache 未接完整调用，限流仅实例内有效 | 不作为新研究资料库或并发配额保障；当前按请求处理供应商限额并报告限流 | 先测现有并发，只有实际配额冲突再调整调用批次，不建中央调度器 |
| G-08 | 历史一致预期、结构化产业链量价／客户关系未确认 | 核查现有权限；公开披露与研报补具体证据、标注估算，不自动采购 | 不把分析师个人假设称一致预期，不伪造完整历史横截面或供应链数据库 |

缺口本身不删除功能需求。数据确实无法获得时可交受限研究，但不得把它计入 spec 的完整案例；最终验收未满足即明确保留未完成项，不能为“通过”改标。

## 每次调用的最小证据

来源结果保存：操作、实际来源、对象、观察时点、获取时点、口径、覆盖、数据文件与错误说明。缺口保存：所缺内容、影响的结论／实验、尝试过的既有源和网页路径、结果及下一动作。它们是事实记录，不需要审批流或缺口状态机。

底层结果区分成功、部分成功和失败；空数据、未授权、不支持、限流、过期、冲突分别给原因。历史缺口不会因为下一次成功自动消失，也不会覆盖当时判断。

持仓与账户数据只放私有运行目录；凭证沿用受保护环境配置或显式秘密文件，不写入请求 JSON、报告、共享模板或 Git。`sec-analysis.env` 的存在不作为新程序自动加载它的理由。

前置检查须先回答三市场完整案例是否有合格数据路径。公开资料或既有导出导入只是补证渠道，不预设能找到完整序列。若 G-01 等无法补齐，明确受阻的成功标准并单独报用户；继续独立工作，但不冻结一份声称全部验收可达的计划，也不擅自扩供应商。数据受阻不等于框架方法可以省略。
